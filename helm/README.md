First-party Helm charts. **Scaffold — populated in

## Helm *and* Kustomize — the division of labour

This platform uses both, each for what it is actually good at. Using one for
everything is a dogma position; using both with a clear boundary is a judgement call,
and the boundary is this:

| | Helm | Kustomize |
| --- | --- | --- |
| **Used for** | Parameterised, reusable packages: one chart rendering N similar services; installing third-party components | Environment differences over a fixed base |
| **Strength** | Templating, conditionals, dependency management, versioned releases | No templating language; patches are declarative and diffable |
| **Weakness** | Go templates become unreadable fast; a chart with 40 conditionals is a program, not config | Poor at generating many similar resources from one definition |

**The rule:** if the difference between two outputs is *which environment*, use a
Kustomize overlay. If the difference is *which service* or *which install*, use a
Helm chart value.

Concretely: a shared `web-service` chart renders frontend/api/worker (same shape,
different values) — that is Helm. Making prod run 6 replicas with different resource
limits and a different hostname — that is a Kustomize overlay patching the rendered
base. Third-party components (Prometheus, Argo CD, cert-manager) are installed from
upstream charts with values files kept in their own component directories.

## Planned charts

```
helm/
├── web-service/          # generic chart: Deployment+Service+Ingress+HPA+PDB
│   ├── Chart.yaml
│   ├── values.yaml       # safe, secure defaults
│   ├── values.schema.json # JSON Schema — fails fast on bad input, self-documents
│   ├── templates/
│   └── README.md         # generated by helm-docs
└── platform-addons/      # umbrella chart for cluster addons, if it earns its keep
```

`values.schema.json` is not optional here. A chart without a schema fails at apply
time with a Kubernetes validation error three layers from the actual mistake; with a
schema it fails at `helm template` time pointing at the wrong key.

## Standards

- `helm lint` and `helm template` clean, validated by `kubeconform` against the
  target Kubernetes version — enforced in CI from Phase 5.
- Secure defaults in `values.yaml`: non-root, read-only root filesystem, dropped
  capabilities, resource requests and limits set, probes defined. A user must
  explicitly opt *out* of security, never opt in.
- Chart version bumped on every change; app version tracks the image tag.
- No secrets in values files, ever. Secret references only — the values come from
  the External Secrets Operator (Phase 8).
